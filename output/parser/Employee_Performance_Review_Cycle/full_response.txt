## Process Elements Summary

### Tasks

1. **userTask("Set Employee Goals")** - Managers establish performance objectives for each employee at fiscal year start
2. **userTask("Track Progress")** - Managers monitor employee performance through regular check-ins
3. **userTask("Document Achievements")** - Managers record employee accomplishments and areas for improvement
4. **userTask("Complete Self-Assessment")** - Employees evaluate their own performance
5. **userTask("Provide Feedback")** - Managers give formal performance reviews
6. **userTask("Make Decisions")** - Determine promotions, bonuses, or training based on evaluation
7. **userTask("Set New Objectives")** - Establish updated goals for next performance cycle

### Gateways

1. **XOR Gateway** - Decision point for performance evaluation outcome
2. **AND Gateway** - Parallel execution of self-assessment and manager feedback

### Events

1. **startEvent("Performance Review Process Starts")** - Process begins at fiscal year start
2. **endEvent("Performance Review Complete")** - Process concludes with updated objectives

### Subprocesses

None identified - all tasks form linear sequence with parallel feedback component

## BPMN Pseudocode

```
startEvent("Performance Review Process Starts")
userTask("Set Employee Goals")
userTask("Track Progress")
userTask("Document Achievements")
AND:
    userTask("Complete Self-Assessment")
    userTask("Provide Feedback")
END_AND
userTask("Make Decisions")
userTask("Set New Objectives")
endEvent("Performance Review Complete")
```

### Key Design Decisions

1. **Parallel Feedback**: Used AND gateway for self-assessment and manager feedback since these activities are truly independent and occur simultaneously during formal review phase
2. **Linear Sequence**: Maintained simple linear flow for goal setting, tracking, and documentation to emphasize chronological progression
3. **Core Elements**: Focused on essential tasks and events while avoiding unnecessary complexity
4. **Boundary Events**: None used as no time constraints or error scenarios were explicitly mentioned
5. **Subprocesses**: Not deployed as all tasks form cohesive, linear sequence with one clear parallel component

This design emphasizes the natural progression of the performance review process while maintaining clean, readable flow with core BPMN elements.
