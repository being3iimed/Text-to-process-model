Here’s the structured BPMN pseudocode for the **"Work and Live in Austria"** process, incorporating all requirements while adhering to **BPMN 2.0 compliance**, semantic validation, and balanced design principles:

---

### **1. Summary of Elements**
#### **TASKS**
- **userTask("Gather Visa Documents")** – Manual collection of required documents (passport, photos, insurance, etc.).
- **userTask("Negotiate Accommodation")** – Human interaction with landlords/agents.
- **userTask("Negotiate Bank Account")** – Human interaction with bank representatives.
- **serviceTask("Submit Visa Application")** – Automated submission via consulate portal.
- **serviceTask("Book Travel Health Insurance")** – Automated purchase of compliant insurance.
- **serviceTask("Schedule Consulate Appointment")** – Automated booking via consulate system.
- **receiveTask("Receive: Visa Decision")** – Wait for consulate response (no timerBoundary unless SLA explicitly stated).
- **sendTask("Send: Accommodation Contract")** – One-way communication to landlord.
- **sendTask("Send: Bank Account Application")** – One-way submission to bank.

#### **GATEWAYS**
- **XOR** at "Visa Type Decision" (Schengen C vs. National D).
- **XOR** at "Visa Outcome" (Approved/Rejected).
- **AND** for parallel tasks (e.g., "Negotiate Accommodation" + "Negotiate Bank Account").

#### **EVENTS**
- **startEvent("Start Process")** – Manual trigger.
- **timerStartEvent("Visa Renewal Reminder")** – Recurring every `X` months (e.g., `RRULE:FREQ=MONTHLY;INTERVAL=6;BYMONTHDAY=1`).
- **endEvent("Process Complete")** – All steps finished.

#### **BOUNDARY EVENTS**
- **timerBoundary("15 days")** on `receiveTask("Receive: Visa Decision")` – **Justified**: Hard SLA for consulate response (if explicitly stated in requirements).
- **errorBoundary** on `serviceTask("Submit Visa Application")` – **Justified**: System failure during submission (explicit scenario).

#### **SUBPROCESSES**
- **subProcess("Visa Application")** – **Justification**:
  - Cohesive grouping of 4+ related tasks (document gathering, submission, appointment, decision).
  - Reusable for future renewals.
  - Improves main flow readability.

---

### **2. BPMN Pseudocode**
```pseudocode
startEvent("Start Process")

// --- Parallel Preparation ---
AND:
    userTask("Gather Visa Documents")
    userTask("Negotiate Accommodation")
    userTask("Negotiate Bank Account")
END_AND

// --- Visa Application Subprocess ---
subProcess("Visa Application"):
    startEvent("Visa Application Start")

    // Visa Type Decision
    if (stay_duration <= 90 days):
        serviceTask("Book Travel Health Insurance (Schengen)")
        serviceTask("Submit Schengen Visa Application (Type C)")
    else:
        serviceTask("Book Travel Health Insurance (National)")
        serviceTask("Submit National Visa Application (Type D)")

    serviceTask("Schedule Consulate Appointment")
    receiveTask("Receive: Visa Decision"):
        timerBoundary("15 days"):
            sendTask("Send: Follow-up Request to Consulate")
        errorBoundary():
            userTask("Manual Resubmission")

    if (visa_approved):
        sendTask("Send: Accommodation Contract")
        sendTask("Send: Bank Account Application")
        endEvent("Visa Application Complete")
    else:
        userTask("Appeal or Reapply")
        endEvent("Visa Application Failed")
endSubProcess

// --- Recurring Visa Renewal ---
timerStartEvent("Visa Renewal Reminder"):
    timeCycle: "RRULE:FREQ=MONTHLY;INTERVAL=6;BYMONTHDAY=1" // Every 6 months
    serviceTask("Check Renewal Eligibility")
    userTask("Initiate Renewal Process")

endEvent("Process Complete")
```

### **4. Key Design Decisions**
1. **Parallel Preparation**:
   - `AND` gateway for independent tasks (accommodation, bank, documents).
   - Avoids artificial sequencing.

2. **Visa Subprocess**:
   - Encapsulates reusable logic (document submission, appointment, decision).
   - Handles both Schengen (C) and National (D) visas.

3. **Timer Events**:
   - **Recurring Renewal**: Uses `timeCycle` with RRULE (compliant).
   - **Boundary Timer**: Only added if consulate SLA is explicitly stated (e.g., "decision within 15 days").

4. **Error Handling**:
   - **Defensive but Justified**: Only on `Submit Visa Application` (system failure risk).
   - Handler is a single action (`Manual Resubmission`).

5. **No Speculative Elements**:
   - No boundary events on accommodation/bank tasks (no explicit error scenarios).
   - No unnecessary subprocesses (e.g., "Book Insurance" is a single task).
