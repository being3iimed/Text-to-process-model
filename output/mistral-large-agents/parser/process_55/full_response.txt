- `startEvent("Begin Central Venous Catheterization")` - Manual trigger
- `endEvent("Procedure Complete")` - Successful completion

#### **BOUNDARY EVENTS**
- **None** (No explicit SLAs or error handling mentioned in description)

#### **SUBPROCESSES**
- **None** (All steps are linear or simple branches; no cohesive grouping needed)

### **2. BPMN Pseudocode**

```pseudocode
startEvent("Begin Central Venous Catheterization")

// Preparation Phase
userTask("Prepare implements")
userTask("Wash hands and wear sterile clothes")
userTask("Clean puncture area")
userTask("Drape puncture zone")

// Ultrasound Setup
userTask("Configure ultrasound")
userTask("Apply gel to probe")
userTask("Cover probe and apply sterile gel")
userTask("Position probe and patient")

// Vein Identification (XOR: 3 methods)
if (use_anatomic_identification):
    userTask("Identify vein via anatomy")
else if (use_doppler_identification):
    userTask("Identify vein via Doppler")
else: // Default: compression
    userTask("Identify vein via compression")

// Puncture and Verification
userTask("Anesthetize patient")
userTask("Puncture vein")
userTask("Check blood return")

// Blood Return Check (XOR)
if (blood_return_correct):
    userTask("Drop probe and remove syringe")
    userTask("Install guidewire")
    userTask("Remove trocar")

    // Wire Position Check (OR: long/short axis)
    OR:
        userTask("Check wire in long axis")
        userTask("Check wire in short axis")
    END_OR

    userTask("Verify wire position")

    // Wire Position Verification (XOR)
    if (wire_in_good_position):
        userTask("Widen pathway")
        userTask("Advance catheter")
        userTask("Remove guidewire")
        userTask("Verify flow and reflow")
        userTask("Check catheter position")
        endEvent("Procedure Complete")
    else:
        // Return to puncture step
        userTask("Puncture vein") // Loop back
else: // Incorrect blood return
    // Return to puncture step
    userTask("Puncture vein") // Loop back
```

### **4. Key Design Decisions**
1. **No Subprocesses**:
   - All steps are either linear or simple branches (XOR/OR).
   - No cohesive grouping meets the **Three-Question Necessity Test** (e.g., "ultrasound setup" is only 2 tasks).

2. **No Boundary Events**:
   - No explicit SLAs (e.g., "must complete within X time") or error scenarios (e.g., "if ultrasound fails") mentioned.
   - **Critical**: Boundary events are **only** added for **explicit** requirements (per gating criteria).

3. **OR Gateway for Wire Checks**:
   - Both long/short axis checks may be performed (non-exclusive), justifying an **inclusive gateway (OR)**.

4. **Explicit Loops**:
   - Incorrect blood return or wire position **explicitly loops back** to `Puncture vein` (no hidden transitions).

5. **Label Clarity**:
   - All conditional flows have **descriptive labels** (e.g., `use_doppler_identification`).

---
### **5. Assumptions**
- **Vein Identification Methods**: Assumed to be mutually exclusive (only one used per procedure). If multiple methods are *always* used, replace the XOR with an **AND gateway**.
- **Wire Position Checks**: Assumed both long/short axis checks *may* be performed (hence OR). If only one is used, replace with XOR.
- **No Time Constraints**: No SLAs or delays mentioned, so no timer events/boundaries added.

---
### **6. Suggested Improvements (If Requirements Change)**
1. **Add Boundary Events** if:
   - A hard time limit is introduced (e.g., "procedure must complete in 30 minutes").
   - Explicit error handling is needed (e.g., "if ultrasound fails, use backup method").

2. **Create Subprocesses** if:
   - Ultrasound setup or catheter advancement becomes a **reused component** (e.g., "Standard Ultrasound Protocol").
   - Steps like "Verify flow and reflow" involve **multiple sub-steps** (e.g., "Flow Verification Protocol").

3. **Add Parallel Gateways** if:
   - Tasks like "Prepare implements" and "Configure ultrasound" can occur **simultaneously**.

---
**Final Note**: This design prioritizes **clinical accuracy** and **BPMN validity**. All loops, gateways, and tasks are **explicitly traceable** to the original description, with no speculative elements.
