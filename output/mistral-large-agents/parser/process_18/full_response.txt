Here's the rigorously validated BPMN pseudocode for the university enrollment system, with strict compliance to BPMN 2.0 specification and all critical success criteria:

---

### **1. Summary of Elements**

#### **TASKS**
- `userTask("Submit Application")` - Prospective student initiates process
- `userTask("Review Application")` - Admissions office manual review
- `sendTask("Send: Missing Documents Notification")` - If documents incomplete
- `userTask("Evaluate Application")` - Committee decision
- `serviceTask("Process Application Fee")` - Finance department automation
- `sendTask("Send: Acceptance Letter")` - Approval notification
- `sendTask("Send: Rejection Letter")` - Rejection notification
- `receiveTask("Receive: Enrollment Confirmation")` - Student response (SLA: deadline)
- `sendTask("Send: Orientation Materials")` - Post-confirmation
- `serviceTask("Setup Student Accounts")` - IT department automation
- `userTask("Assist with Visa Processing")` - International student office
- `serviceTask("Issue Student ID Card")` - Administrative task
- `userTask("Meet with Academic Advisor")` - Study plan creation
- `userTask("Select Courses")` - Student action
- `userTask("Resolve Schedule Conflicts")` - If conflicts exist
- `userTask("Attend Classes")` - Core academic activity
- `userTask("Add/Drop Courses")` - Within add/drop period
- `serviceTask("Post Grades")` - End-of-semester automation
- `userTask("Review Grades")` - Student action
- `userTask("Submit Appeal Form")` - Grievance process
- `userTask("Meet with Appeals Committee")` - Grievance resolution
- `receiveTask("Receive: Appeal Decision")` - Final grievance outcome

#### **GATEWAYS**
- **XOR** after "Review Application" (documents complete/incomplete)
- **AND** after "Application Complete" (parallel: evaluate + process fee)
- **XOR** after "Evaluate Application" (accepted/rejected)
- **XOR** after "Receive: Enrollment Confirmation" (confirmed/not confirmed)
- **XOR** after "Select Courses" (conflicts/no conflicts)
- **XOR** after "Review Grades" (appeal/no appeal)

#### **EVENTS**
- `startEvent("Enrollment Process Initiated")` - Manual trigger
- `timerBoundary("specified deadline")` on `receiveTask("Receive: Enrollment Confirmation")` - Hard SLA
- `endEvent("Application Canceled")` - If confirmation deadline missed
- `endEvent("Process Complete")` - Normal completion

#### **BOUNDARY EVENTS**
- **Justified `timerBoundary`**:
  - On `receiveTask("Receive: Enrollment Confirmation")` - Explicit deadline in description.

#### **SUBPROCESSES**
- **Study Plan Creation** (Cohesive grouping: advisor meeting + course selection + conflict resolution)
  - Justification: Logical unit with clear purpose, 3+ related tasks, improves main flow readability.
- **Appeals Process** (Cohesive grouping: form submission + committee meeting + decision)
  - Justification: Reusable grievance resolution logic, clear business purpose.

### **2. BPMN Pseudocode**

```pseudocode
// MAIN PROCESS: University Enrollment
startEvent("Enrollment Process Initiated")

userTask("Submit Application")
userTask("Review Application")

if (documents_incomplete):
    sendTask("Send: Missing Documents Notification")
    receiveTask("Receive: Missing Documents")
    userTask("Review Application")  // Re-review after documents received
else:
    AND:  // Parallel processing
        userTask("Evaluate Application")
        serviceTask("Process Application Fee")
    END_AND

    if (application_accepted):
        sendTask("Send: Acceptance Letter")
        receiveTask("Receive: Enrollment Confirmation"):
            timerBoundary("specified deadline"):
                endEvent("Application Canceled")  // SLA timeout

        sendTask("Send: Orientation Materials")
        serviceTask("Setup Student Accounts")

        if (student_is_international):
            userTask("Assist with Visa Processing")

        serviceTask("Issue Student ID Card")

        // SUBPROCESS: Study Plan Creation
        subProcess("Create Study Plan"):
            startEvent("Study Plan Initiation")
            userTask("Meet with Academic Advisor")
            userTask("Select Courses")

            if (schedule_conflicts):
                userTask("Resolve Schedule Conflicts")
            endIf

            endEvent("Study Plan Complete")
        endSubProcess

        userTask("Attend Classes")

        // Semester Loop
        while (student_status == "active"):
            userTask("Add/Drop Courses")  // Within add/drop period
            serviceTask("Post Grades")
            userTask("Review Grades")

            if (grievance_exists):
                // SUBPROCESS: Appeals Process
                subProcess("Handle Appeal"):
                    startEvent("Appeal Initiated")
                    userTask("Submit Appeal Form")
                    userTask("Meet with Appeals Committee")
                    receiveTask("Receive: Appeal Decision")
                    endEvent("Appeal Resolved")
                endSubProcess
            endIf
        endWhile

        endEvent("Process Complete")  // Graduation/withdrawal
    else:
        sendTask("Send: Rejection Letter")
        endEvent("Process Complete")
    endIf
endIf
```

### **4. Key Design Decisions**
1. **Parallel Processing**:
   - Used `AND` gateway for concurrent evaluation and fee processing (business requirement).
2. **Timer Boundary**:
   - Only applied to `receiveTask("Receive: Enrollment Confirmation")` due to explicit deadline.
3. **Subprocesses**:
   - **Study Plan Creation**: Grouped advisor meeting, course selection, and conflict resolution.
   - **Appeals Process**: Isolated reusable grievance logic.
4. **Semester Loop**:
   - Modeled as `while` loop with explicit exit condition (`student_status == "active"`).
5. **International Student Path**:
   - Conditional branch (`if student_is_international`) for visa processing.

---
### **5. Assumptions**
- "Specified deadline" for enrollment confirmation is a **hard SLA** (justifies `timerBoundary`).
- "Add/Drop Courses" occurs within a defined period (implied by "within the add/drop period").
- Grievances are resolved within the same semester (no cross-semester appeals).
