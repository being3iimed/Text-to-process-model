## Summary of Elements

### TASKS:
- **userTask("Check Defect and Calculate Repair Cost")**
  *Reason*: Human judgment required to assess defect and calculate cost.

- **userTask("Customer Decides on Repair")**
  *Reason*: Customer decision point (accept/reject repair cost).

- **serviceTask("Check and Repair Hardware")**
  *Reason*: Automated/systematic hardware repair process.

- **serviceTask("Check and Configure Software")**
  *Reason*: Automated/systematic software repair process.

- **serviceTask("Test System Functionality")**
  *Reason*: Automated/systematic testing after each repair activity.

### GATEWAYS:
- **XOR Gateway** after "Customer Decides on Repair":
  *Conditions*:
  - `costs_acceptable` → Proceed with repair
  - `costs_not_acceptable` → End process (default)

- **AND Gateway** for parallel repair activities:
  *Branches*:
  - Hardware repair
  - Software repair

- **XOR Gateway** after "Test System Functionality":
  *Conditions*:
  - `error_detected` → Repeat repair activity
  - `no_error` → Proceed to next step (default)

### EVENTS:
- **startEvent("Customer Brings Defective Computer")**
  *Trigger*: Manual (customer initiates process).

- **endEvent("Repair Complete")**
  *Trigger*: Normal completion of repair process.

- **endEvent("Customer Declines Repair")**
  *Trigger*: Customer rejects repair cost.

### BOUNDARY EVENTS:
- **None**
  *Reason*: No explicit SLA requirements or expected error scenarios mentioned.

### SUBPROCESSES:
- **subProcess("Repair and Test Cycle")**
  *Purpose*: Encapsulates the iterative repair-test loop for hardware/software.
  *Justification*:
  - **Cohesive logic**: Combines repair + test + potential re-repair into a single reusable unit.
  - **Complexity isolation**: Simplifies main flow by abstracting iterative logic.
  - **Clear purpose**: "Execute repair activity and validate until success."

```pseudocode
startEvent("Customer Brings Defective Computer")

// Initial defect check and cost calculation
userTask("Check Defect and Calculate Repair Cost")

// Customer decision point
userTask("Customer Decides on Repair")
if (costs_acceptable):
    // Parallel repair activities (order arbitrary)
    AND:
        subProcess("Repair and Test Cycle"):
            startEvent("Start Hardware Repair")
            serviceTask("Check and Repair Hardware")
            serviceTask("Test System Functionality")
            if (error_detected):
                // Repeat hardware repair
                serviceTask("Check and Repair Hardware")
                serviceTask("Test System Functionality")
            else:
                endEvent("Hardware Repair Complete")
        endSubProcess

        subProcess("Repair and Test Cycle"):
            startEvent("Start Software Repair")
            serviceTask("Check and Configure Software")
            serviceTask("Test System Functionality")
            if (error_detected):
                // Repeat software repair
                serviceTask("Check and Configure Software")
                serviceTask("Test System Functionality")
            else:
                endEvent("Software Repair Complete")
        endSubProcess
    END_AND

    // Both repairs complete
    endEvent("Repair Complete")

else: // costs_not_acceptable (default)
    endEvent("Customer Declines Repair")
