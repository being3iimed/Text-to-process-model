<final_notes>

## Key Design Decisions

1. **Parallelism Handling**:
   - Used AND gateway to model concurrent preparation by kitchen, sommelier, and waiter.
   - **Validation**: Confirmed these tasks are independent in the description ("while the kitchen and sommelier are doing their tasks, the waiter readies a cart").

2. **No Subprocesses**:
   - Rejected subprocess for "Waiter Tasks" (Prepare Cart + Nonalcoholic Drinks) because:
     - Only 2 tasks (fails Three-Question Test Q2: needs 3+ tasks).
     - No clear reuse or complexity isolation benefit.

3. **No Boundary Events**:
   - "Waiter may wait to do billing" is a **discretionary delay**, not a hard SLA → no `timerBoundary`.
   - No explicit error scenarios (e.g., kitchen fails, sommelier unavailable) → no `errorBoundary`.

4. **Implicit vs. Explicit Convergence**:
   - Initially modeled implicit convergence after parallel tasks.
   - **Correction**: Added explicit converging AND gateway for BPMN best practices (avoids ambiguity).

5. **Timer Compliance**:
   - No schedules/delays mentioned → no timer events needed.
   - If future revision adds SLAs (e.g., "deliver within 30 minutes"), would add:
     ```pseudocode
     userTask("Deliver Order to Guest"):
         timerBoundary("PT30M"):
             sendTask("Send: apology to guest for delay")
     ```

</final_notes>
