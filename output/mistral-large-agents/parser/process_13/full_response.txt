### TASKS:
- **userTask("Log Complaint")** - Customer service manually logs complaint details
- **serviceTask("Assign to Department")** - System automatically routes to correct team
- **userTask("Review Complaint")** - Department investigates validity and refund justification
- **sendTask("Send: Decision Notification")** - System notifies customer of decision
- **serviceTask("Process Refund")** - Financial team executes reimbursement
- **userTask("Mark as Resolved")** - System marks case as closed

<design_rationale>

## Key Design Decisions

1. **No Boundary Events**:
   - Description lacked hard SLAs (e.g., "must respond within X hours")
   - No expected error scenarios (e.g., "if system fails during refund")
   - *Compliance*: Avoids speculative patterns per `<boundary_event_gating>`

2. **No Subprocesses**:
   - All tasks are part of a single linear investigation → resolution flow
   - Single decision point (refund approval) doesn’t warrant abstraction
   - *Compliance*: Passes `<subprocess_validation>` Three-Question Test (Q1: "No single cohesive purpose beyond main flow")

3. **XOR Gateway**:
   - Binary decision (refund: yes/no) with mutually exclusive outcomes
   - Default flow handles rejection case explicitly
   - *Compliance*: Meets `<gateway_convergence>` requirements

4. **Receive Task for Feedback**:
   - Marked as optional (no timerBoundary) since description didn’t specify SLA
   - *Compliance*: Avoids defensive timer addition per `<timer_positioning>`
