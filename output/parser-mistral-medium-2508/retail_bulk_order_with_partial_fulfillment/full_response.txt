## Summary of Elements

### TASKS:
- **userTask("Submit Bulk Order")** - Manager initiates bulk order for 500 units across 5 products
- **serviceTask("Check Inventory Availability")** - System verifies stock levels for each product
- **serviceTask("Reserve Order")** - System locks inventory for confirmed items
- **serviceTask("Schedule Immediate Packing")** - System triggers warehouse packing process
- **sendTask("Send: stock shortage notification")** - System alerts manager of insufficient stock
- **userTask("Select Fulfillment Option")** - Manager chooses partial shipment or wait
- **serviceTask("Split Order")** - System divides order into available/backordered items
- **serviceTask("Create Backorder")** - System generates backorder record
- **serviceTask("Hold Order Pending")** - System places order in waiting status
- **serviceTask("Ship Available Items")** - Warehouse dispatches partial shipment
- **serviceTask("Ship Complete Order")** - Warehouse dispatches full order
- **serviceTask("Update Inventory")** - System adjusts stock levels post-shipment
- **receiveTask("Receive: stock arrival notification")** - System detects backordered items received

### GATEWAYS:
- **XOR** after inventory check: all available vs. any shortage
- **XOR** for manager decision: partial shipment vs. wait
- **XOR** after stock arrival: was partial shipped? (complete vs. remaining)

### EVENTS:
- **startEvent("Bulk Order Submission")** - Manual trigger by manager
- **intermediateEvent(timerBoundary("24 hours"))** - SLA for manager decision
- **endEvent("Order Fulfilled")** - All items shipped
- **endEvent("Order Cancelled")** - If manager cancels during wait

### BOUNDARY EVENTS:
- **timerBoundary("24 hours")** on userTask("Select Fulfillment Option")
  - **Justification**: Explicit SLA for manager response to shortage notification
  - **Handler**: sendTask("Send: escalation to director")

### SUBPROCESSES:
- **Subprocess "Order Fulfillment"** (contains: reserve, schedule packing, ship)
  - **Justification**: Cohesive fulfillment logic (4 related tasks) with clear purpose
  - **Passes Necessity Test**:
    1. Single sentence: "Handles all physical fulfillment operations"

## BPMN Pseudocode

```pseudocode
startEvent("Bulk Order Submission")

// Initial order processing
userTask("Submit Bulk Order")
serviceTask("Check Inventory Availability")

if (all_products_available):
    subProcess("Order Fulfillment"):
        startEvent("Fulfillment Start")
        serviceTask("Reserve Order")
        serviceTask("Schedule Immediate Packing")
        serviceTask("Ship Complete Order")
        serviceTask("Update Inventory")
        endEvent("Fulfillment Complete")
    endSubProcess
    endEvent("Order Fulfilled")

else: // Any product shortage
    sendTask("Send: stock shortage notification")

    // Manager decision with 24h SLA
    userTask("Select Fulfillment Option"):
        timerBoundary("24 hours"):
            sendTask("Send: escalation to director")

    if (manager_chooses_partial):
        serviceTask("Split Order")
        subProcess("Order Fulfillment"):
            startEvent("Partial Fulfillment Start")
            serviceTask("Reserve Order")
            serviceTask("Schedule Immediate Packing")
            serviceTask("Ship Available Items")
            serviceTask("Update Inventory")
            endEvent("Partial Fulfillment Complete")
        endSubProcess

        serviceTask("Create Backorder")
        receiveTask("Receive: stock arrival notification")
        serviceTask("Ship Remaining Items")
        serviceTask("Update Inventory")
        endEvent("Order Fulfilled")

    else: // Manager chooses to wait
        serviceTask("Hold Order Pending")
        receiveTask("Receive: stock arrival notification")
        subProcess("Order Fulfillment"):
            startEvent("Delayed Fulfillment Start")
            serviceTask("Reserve Order")
            serviceTask("Schedule Immediate Packing")
            serviceTask("Ship Complete Order")
            serviceTask("Update Inventory")
            endEvent("Delayed Fulfillment Complete")
        endSubProcess
        endEvent("Order Fulfilled")
```

## Critical Path Analysis

### Happy Path (All Items Available):
1. Submit Order → Check Inventory → [all_available]
2. → Reserve → Pack → Ship Complete → Update Inventory
**Duration**: ~1 hour (fulfillment subprocess)

### Shortage Path (Partial Shipment):
1. Submit → Check → [shortage] → Notify Manager
2. → Manager chooses partial → Split Order
3. → Partial Fulfillment → Create Backorder
4. → Wait for stock → Ship Remaining → Complete
**Duration**: 1 day (SLA) + stock lead time + 1 hour fulfillment

### Shortage Path (Wait for Stock):
1. Submit → Check → [shortage] → Notify Manager
2. → Manager chooses wait → Hold Order
3. → Wait for stock → Full Fulfillment → Complete
**Duration**: Stock lead time + 1 hour fulfillment

### Escalation Path:
1. Manager doesn't respond within 24h → Escalation sent
2. → Manual resolution required
