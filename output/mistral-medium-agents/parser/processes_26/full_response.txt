Here's the structured BPMN pseudocode for the "Becoming A Parent" maternity leave process, with rigorous semantic validation and compliance checks:

---
### **1. Summary of Elements**

#### **TASKS**
- `userTask("Fetch maternity leave models")` - Research available leave models (duration, parental split)
- `userTask("Select maternity leave model")` - Parent chooses preferred model
- `userTask("Collect required documents")` - Gather IDs, employment proof, medical certificates
- `serviceTask("Validate documents")` - System checks completeness
- `sendTask("Send: notification to Social Security")` - Formal leave request
- `sendTask("Send: notification to Company")` - Employer notification
- `receiveTask("Receive: confirmation from Social Security")` - Await approval
- `receiveTask("Receive: confirmation from Company")` - Await employer acknowledgment
- `userTask("Review extension options")` - Parent decides if extension is needed
- `sendTask("Send: extension request (if applicable)")` - Optional follow-up

#### **GATEWAYS**
- **XOR** after "Select model" (proceed only if valid selection)
- **AND** for parallel notifications (Social Security + Company)
- **XOR** for extension decision (yes/no)

#### **EVENTS**
- `startEvent("Maternity Leave Planning Initiated")` - Manual trigger
- `endEvent("Leave Process Complete")` - Normal completion
- `endEvent("Extension Requested")` - Alternative completion

#### **BOUNDARY EVENTS**
- **None** (no hard SLAs or expected errors in this process)

#### **SUBPROCESSES**
- **None** (all tasks are linear/cohesive; no grouping needed)

---
### **2. BPMN Pseudocode**
```pseudocode
startEvent("Maternity Leave Planning Initiated")

// Phase 1: Model Selection
userTask("Fetch maternity leave models")
userTask("Select maternity leave model")
if (model_selected == "valid"):
    userTask("Collect required documents")
    serviceTask("Validate documents")
else:
    endEvent("Process Aborted - Invalid Model")
    // Early exit if no valid model chosen

// Phase 2: Notifications (Parallel)
AND:
    sendTask("Send: notification to Social Security")
    sendTask("Send: notification to Company")
END_AND

// Phase 3: Confirmations (Parallel)
AND:
    receiveTask("Receive: confirmation from Social Security")
    receiveTask("Receive: confirmation from Company")
END_AND

// Phase 4: Extension Decision
userTask("Review extension options")
if (extension_needed == "yes"):
    sendTask("Send: extension request (if applicable)")
    endEvent("Extension Requested")
else:
    endEvent("Leave Process Complete")
```

### **4. Key Design Decisions**
1. **No Timer Events**: Process is parent-driven; no automated schedules.
2. **Parallel Notifications**: Social Security and Company are notified simultaneously (AND gateway).
3. **Extension as Optional Path**: Uses XOR to branch based on parent’s decision.
4. **No Subprocesses**: Tasks are simple and sequential; no need for abstraction.

---
### **5. Assumptions**
- "Notify in time" implies no hard deadlines (thus no `timerBoundary`).
- "Extension" is a binary decision (no complex logic).
- Documents are validated automatically (no manual review task).
