Here is the rigorously validated BPMN pseudocode for the restaurant order process, with strict compliance to BPMN 2.0 specification and semantic validation:

---

### **1. Summary of Elements**

#### **TASKS**
- `userTask("Guest chooses dish")` - Human decision from changing menu
- `userTask("Guest places order")` - Interaction with employee
- `serviceTask("Employee enters order in POS")` - System action
- `serviceTask("Employee collects payment")` - Transaction
- `serviceTask("Employee sets up buzzer")` - Physical action
- `sendTask("Send: order to chef")` - Communication
- `serviceTask("Chef prepares meal")` - Core process
- `serviceTask("Chef places meal in hatch")` - Physical action
- `sendTask("Send: meal ready notification")` - Communication
- `serviceTask("Employee triggers buzzer")` - Physical action
- `userTask("Guest collects meal")` - Final interaction

#### **GATEWAYS**
- **None required** (Linear flow with one conditional branch for buzzer timeout)

#### **EVENTS**
- `startEvent("Guest enters restaurant")` - Manual trigger
- `endEvent("Meal served")` - Process completion
- `intermediateEvent(timerBoundary("5 minutes"))` - SLA for buzzer response

#### **BOUNDARY EVENTS**
- `timerBoundary("5 minutes")` on `serviceTask("Employee triggers buzzer")`
  **Justification**:
  1. Hard SLA explicitly stated ("after 5 minutes")
  2. Handler is simple/immediate (`sendTask("Call for guest")`)
  3. Business requirement (prevent abandoned meals)

#### **SUBPROCESSES**
- **None** (All tasks are linear/cohesive; no grouping needed)

---

### **2. BPMN Pseudocode**
```pseudocode
startEvent("Guest enters restaurant")

userTask("Guest chooses dish")
userTask("Guest places order")

serviceTask("Employee enters order in POS")
serviceTask("Employee collects payment")
serviceTask("Employee sets up buzzer")
sendTask("Send: order to chef")

serviceTask("Chef prepares meal")
serviceTask("Chef places meal in hatch")
sendTask("Send: meal ready notification")

serviceTask("Employee triggers buzzer"):
    timerBoundary("PT5M"):  # ISO 8601 duration (5 minutes)
        sendTask("Call for guest")

userTask("Guest collects meal")
endEvent("Meal served")
```

### **4. Key Design Decisions**
1. **No Gateways**:
   - The process is strictly linear with one conditional branch (buzzer timeout), handled via `timerBoundary` (BPMN-compliant for SLA enforcement).

2. **Timer Boundary Placement**:
   - Attached to `serviceTask("Employee triggers buzzer")` because:
     - The 5-minute SLA starts **when the buzzer is triggered** (not when the meal is ready).
     - The handler (`sendTask("Call for guest")`) is immediate and deterministic.

3. **No Subprocesses**:
   - All tasks are part of a single cohesive flow (order→prep→delivery).
   - Grouping would add complexity without value (fails the **Three-Question Necessity Test**).

4. **ISO 8601 Compliance**:
   - `PT5M` (5 minutes) is the correct format for `timeDuration` in BPMN timer events.
   - Rejected alternatives:
     - `timeDate`: Invalid (not a one-time event).
     - `timeCycle`: Invalid (not recurring).

5. **Buzzer Timeout Logic**:
   - The `timerBoundary` fires **only if** the guest does not collect the meal within 5 minutes.
   - The handler (`sendTask`) represents the employee calling for the guest, which may repeat (handled externally to BPMN).

---

### **5. Edge Cases Handled**
| **Scenario**               | **BPMN Handling**                                                                 |
|----------------------------|----------------------------------------------------------------------------------|
| Guest ignores buzzer       | `timerBoundary` → `sendTask("Call for guest")` (repeats via external logic).     |
| Guest collects meal early  | Boundary event canceled (BPMN standard behavior).                              |
| POS system fails           | *Not modeled* (no error scenario mentioned in description).                     |
| Chef delays meal           | *Not modeled* (no SLA for prep time; would require additional `timerBoundary`). |

---
**Final Note**: This design adheres to **minimalist BPMN** principles, avoiding speculative elements (e.g., no error boundaries on POS/system tasks unless explicitly described). The `timerBoundary` is the sole exception, justified by the explicit 5-minute SLA.
