### **1. Summary of Elements**

#### **TASKS**
- `userTask("Check Battle.net Account")` - Manual check for existing account
- `userTask("Enter Account Information")` - Manual data entry for new account
- `receiveTask("Receive: confirmation email")` - Wait for email with link
- `userTask("Click Confirmation Link")` - Manual action to verify account
- `userTask("Check WoW Subscription")` - Manual check for active subscription
- `userTask("Select Payment Method")` - Manual choice between credit card/bank
- `userTask("Enter Credit Card Info")` - Manual data entry
- `userTask("Enter IBAN/BIC")` - Manual data entry
- `userTask("Log into Game")` - Manual login action
- `userTask("Select Realm/Race/Class")` - Manual character setup
- `userTask("Enter Character Name")` - Manual name input (repeated until available)
- `serviceTask("Check Name Availability")` - Automated system check
- `serviceTask("Generate Character Selfies")` - Automated image generation
- `sendTask("Send: expansion release notification")` - Automated future message

#### **GATEWAYS**
- **XOR** after "Check Battle.net Account" (2 branches: has account / no account)
- **XOR** after "Check WoW Subscription" (2 branches: active / inactive)
- **XOR** after "Select Payment Method" (2 branches: credit card / bank)
- **Loop** for "Enter Character Name" until availability confirmed

#### **EVENTS**
- `startEvent("Start Character Creation")` - Manual trigger
- `messageStartEvent("Expansion Release")` - Future automated trigger for notification
- `endEvent("Character Created")` - Normal completion
- `endEvent("Account Setup Complete")` - Intermediate milestone

#### **BOUNDARY EVENTS**
- **None** (No explicit SLAs or error scenarios mentioned)

#### **SUBPROCESSES**
- **None** (No cohesive logic groups requiring abstraction)

### **2. BPMN Pseudocode**

```pseudocode
// --- MAIN PROCESS: CHARACTER CREATION ---
startEvent("Start Character Creation")

// --- ACCOUNT SETUP (Parallel to Name Brainstorming) ---
AND:
    // --- Path 1: Account Setup ---
    if (battle_net_account_exists):
        userTask("Check Battle.net Account")
        endEvent("Account Setup Complete")
    else:
        userTask("Enter Account Information")
        sendTask("Send: confirmation email")
        receiveTask("Receive: confirmation email")
        userTask("Click Confirmation Link")
        endEvent("Account Setup Complete")
    END_IF

    // --- Path 2: Name Brainstorming (Parallel) ---
    userTask("Brainstorm Character Names")
END_AND

// --- SUBSCRIPTION CHECK ---
if (wow_subscription_active):
    userTask("Check WoW Subscription")
else:
    userTask("Select Payment Method")
    if (payment_method == "credit_card"):
        userTask("Enter Credit Card Info")
    else if (payment_method == "bank_account"):
        userTask("Enter IBAN/BIC")
    END_IF
END_IF

// --- CHARACTER CREATION ---
userTask("Log into Game")
userTask("Select Realm/Race/Class")

// --- NAME SELECTION LOOP ---
LOOP:
    userTask("Enter Character Name")
    serviceTask("Check Name Availability")
UNTIL (name_available)

serviceTask("Generate Character Selfies")
endEvent("Character Created")

// --- FUTURE NOTIFICATION (Separate Process) ---
messageStartEvent("Expansion Release")
sendTask("Send: expansion release notification")
endEvent("Notification Sent")
```

### **4. Key Design Decisions**
1. **Parallel Paths**:
   - Used `AND` gateway to model simultaneous account setup and name brainstorming (as described: *"while you are setting up your account, you can already come up with good character names"*).

2. **Loop for Name Availability**:
   - Explicit `LOOP...UNTIL` structure for iterative name entry until availability is confirmed.

3. **Future Notification**:
   - Modeled as a separate process triggered by `messageStartEvent("Expansion Release")` to avoid mixing concerns.

4. **No Boundary Events**:
   - Omitted due to lack of explicit SLAs or error scenarios in the description.

5. **No Subprocesses**:
   - All logic is linear or conditionally branched; no cohesive groups requiring abstraction.

---
### **5. Assumptions**
- **"Some selfies of your character"**: Interpreted as an automated system task (`serviceTask`).
- **"Another message when expansion is released"**: Modeled as a future-triggered process to avoid blocking the main flow.
- **Payment Methods**: Limited to credit card/bank account as described (no PayPal/etc.).
