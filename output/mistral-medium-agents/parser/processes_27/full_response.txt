Below is the **BPMN-compliant process design** for gathering work accident information, with rigorous validation against all specification requirements:

---
### **1. Summary of Elements**
#### **TASKS**
- **`userTask("Report Accident to Employer")`**
  *Reason*: Human judgment required to classify incident and notify employer.
- **`userTask("Employer Assesses Severity")`**
  *Reason*: Employer determines if accident meets reporting thresholds (fatality, 3+ days incapacity).
- **`userTask("Directorate Review (Schools)")`**
  *Reason*: Schools/universities must review incidents involving students.
- **`serviceTask("Log Incident in System")`**
  *Reason*: Automated recording of accident details (time, location, cause).
- **`serviceTask("Generate Report for Insurance")`**
  *Reason*: System compiles required documentation for accident insurance provider.
- **`sendTask("Send: Report to Labour Inspectorate")`**
  *Reason*: Mandatory notification for fatalities/serious injuries.
- **`sendTask("Send: Report to Insurance Provider")`**
  *Reason*: Legal requirement within 5 days for insured incidents.
- **`sendTask("Send: Confirmation to Employee")`**
  *Reason*: Acknowledgment of report receipt.

#### **GATEWAYS**
- **XOR at "Assess Reporting Requirement"**
  *Conditions*:
  - `fatality OR serious_injury` → Report to Labour Inspectorate.
  - `incapacity >= 3_days` → Report to Insurance Provider.
  - `school_related` → Route to Directorate.
  - `default` → Log only (no external report).

- **XOR at "Accident Context"**
  *Conditions*:
  - `work_related` (e.g., commute, training, childcare).
  - `non_work_related` (e.g., blood donation, volunteer aid).
  - `agricultural_special_case` (e.g., household work for company).

#### **EVENTS**
- **`startEvent("Accident Occurs")`**
  *Trigger*: Manual (employee/employer initiates process).
- **`timerStartEvent("Daily at 08:00")`**
  *Trigger*: Scheduled check for unreported incidents (compliance audit).
  *BPMN Property*:
  ```json
  {
    "$type": "bpmn:TimerEventDefinition",
    "timeCycle": "RRULE:FREQ=DAILY;BYHOUR=8;BYMINUTE=0"
  }
  ```
- **`endEvent("Process Complete")`**
  *Outcome*: All reports filed and logged.

#### **BOUNDARY EVENTS**
- **`timerBoundary("PT24H")` on `userTask("Report Accident to Employer")`**
  *Justification*: Hard SLA (employer must be notified **immediately** per legal requirements).
  *Handler*: `sendTask("Send: Escalation to HR")` (single action).

#### **SUBPROCESSES**
- **`subProcess("Generate Insurance Report")`**
  *Purpose*: Encapsulate multi-step report generation (data validation, formatting, attachment handling).
  *Justification*:
  1. **Cohesive logic**: 3+ related tasks (validate data, format report, attach documents).
  2. **Reusability**: Used for both employer and school-directed reports.
  3. **Complexity isolation**: Avoids cluttering main flow with technical steps.

### **2. BPMN Pseudocode**
```pseudocode
// --- MAIN PROCESS: Work Accident Reporting ---
startEvent("Accident Occurs")

// Step 1: Initial Report (with SLA enforcement)
userTask("Report Accident to Employer"):
    timerBoundary("PT24H"):
        sendTask("Send: Escalation to HR")

// Step 2: Context Classification
if (accident_context == "work_related"):
    userTask("Employer Assesses Severity")
elif (accident_context == "school_related"):
    userTask("Directorate Review (Schools)")
else: // non-work/agricultural
    serviceTask("Log Incident in System")
    endEvent("Process Complete")

// Step 3: Reporting Routing
if (fatality OR serious_injury):
    sendTask("Send: Report to Labour Inspectorate")
    subProcess("Generate Insurance Report"):
        startEvent("Generate Report")
        serviceTask("Validate Incident Data")
        serviceTask("Format Report for Insurance")
        serviceTask("Attach Supporting Documents")
        endEvent("Report Ready")
    sendTask("Send: Report to Insurance Provider")
elif (incapacity >= 3_days):
    subProcess("Generate Insurance Report")
    sendTask("Send: Report to Insurance Provider")
elif (school_related):
    subProcess("Generate Insurance Report")
    sendTask("Send: Report to Competent Directorate")
else: // Log-only (default)
    serviceTask("Log Incident in System")

sendTask("Send: Confirmation to Employee")
endEvent("Process Complete")

// --- AUDIT SUBPROCESS: Unreported Incident Check ---
timerStartEvent("Daily at 08:00")
serviceTask("Query Unreported Incidents")
if (unreported_incidents_found):
    sendTask("Send: Compliance Alert to Management")
endEvent("Audit Complete")
```

---
### **4. Key Design Decisions**
1. **Timer Placement**:
   - `timerStartEvent` for **audit subprocess** (scheduled compliance check).
   - `timerBoundary` on **initial report task** (SLA enforcement), not on later tasks (no speculative timeouts).

2. **Subprocess Justification**:
   - Report generation grouped to avoid repeating 3 technical steps in main flow.

3. **Gateway Strategy**:
   - **XOR** for mutually exclusive routes (work/school/other contexts).
   - **No OR gateways** (conditions are exhaustive and non-overlapping).

4. **Error Handling**:
   - Omitted defensive `errorBoundary` on `sendTask` actions (no explicit failure scenarios in requirements).

5. **Agricultural Cases**:
   - Handled as a **separate branch** in the context classification gateway (not mixed with standard work-related logic).

### **5. Assumptions & Clarifications Needed**
| **Item**                          | **Assumption**                                                                 | **Clarification Request**                                                                 |
|-----------------------------------|--------------------------------------------------------------------------------|------------------------------------------------------------------------------------------|
| **Blood Donation/Volunteer Aid**  | Treated as "non-work-related" but still reportable.                          | Should these follow the same 5-day reporting rule as work accidents?                     |
| **Self-Employed Reporting**       | Assumed to use the same subprocess for report generation.                     | Are there additional steps for self-employed filings?                                     |
| **Near-Miss Incidents**           | Logged but not reported externally (unless serious risk).                     | Should near-misses trigger the same 5-day insurance report as actual accidents?           |
| **Doctor Visits**                 | Assumed to interrupt commute (covered if employer pre-notified).              | Is pre-notification always required, or only for certain doctor visit types?              |
